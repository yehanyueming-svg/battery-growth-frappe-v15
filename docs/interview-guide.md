# 智格用户增长中心面试说明

## 需求理解

项目不是通用 BI，也不是简单新增计数。订阅是可审计的生命周期事实：同一客户重新开通会新增订阅，旧订阅的流失历史保留。报表、大屏和 AI 简报都消费同一个 `analytics.metrics.get_growth_metrics`，避免三个界面出现三套口径。

## 指标口径

日期端点包含在范围内；暂停仍属于在服生命周期，流失从 `churn_date` 当日生效。期初在服、期间新增、期间流失、期末在服形成可解释的增长桥，Summary 流失率使用累计流失除以“期初在服 + 期间新增”。最大跨度限制 36 个月，防止无界扫描。

没有把现有 Python 指标逻辑为了“看起来复杂”改写成大 SQL。当前规模优先正确性、可测试性和单一来源；更大数据量的后续扩展可引入按日事实表、增量聚合和数据库索引分析。

## 权限边界

两个大屏 API 都先检查 `Service Subscription` Read 权限，再解析筛选或执行指标服务。生成简报只接受 POST。客户端不重算指标，只呈现固定聚合 Schema。外部 Provider 仅收到白名单聚合字段，不包含客户姓名、手机号、联系人、客户编码或单条订阅。

## Mock 与启动幂等

Mock 生成器使用固定种子并标记 `is_mock = 1`。普通调用检测到 Mock 后跳过；显式 rebuild 也只删除 Mock，不触碰用户数据。Docker `site-init` 又在站点、App 和数据三个层面分别做存在性判断，因此中断后可以重跑，第二次启动仍保持 240 条。

## Docker 取舍

使用固定提交的官方 `frappe_docker` 和 layered Containerfile，而不是复制 Frappe 核心代码或把所有进程塞进单容器。App 在镜像构建时加入，MariaDB/Redis 不发布端口，只有 frontend 暴露 `8080`。命名卷提供站点与数据库持久化；`down` 保留数据，`reset` 需要显式确认和 owner 校验。

镜像里的 App `.git` 会被官方 Containerfile 删除，所以可复核性依赖构建时的精确 App ref、`CACHE_BUST` 和 OCI revision 标签。这个选择尊重不可变镜像，也不伪造容器内 Git 状态。

## AI 缓存与 AI 降级

默认本地规则是完整主路径，不依赖网络和密钥。OpenAI-compatible 模式只处理严格脱敏的聚合快照；超时、非 2xx、过大响应、非法 JSON 或 Schema 错误都记录去敏摘要并回退规则。

页面第一次“生成简报”传 `force=0`，相同聚合快照可复用服务端缓存；结果显示后才切换为“重新生成”并传 `force=1`。筛选或数据刷新会使当前简报失效，异步序列号阻止旧响应覆盖新 KPI。

## 工程质量

轻量 CI 运行 Ruff、JSON、Python dependency-light tests、ESLint、Prettier、大屏模块/浏览器契约、Compose 归一化和双平台脚本语法。手动或发布标签 CI 才承担完整镜像、空卷站点、Bench、重复启动和持久化验收，避免每次提交都支付完整 Frappe 构建成本。

## 后续扩展

- 生产部署补充 TLS、秘密管理、备份恢复、监控、容量规划和高可用，而不是把本地演示密码带入生产。
- 数据量增长后增加生命周期事实表/物化聚合、查询画像和缓存失效策略。
- 视觉回归可接入真实 Frappe Playwright 会话，固定三种视口并保留可审计截图。
- Provider 可增加供应商适配器、成本/延迟指标和人工确认流程，但 AI 文案始终不成为业务事实或自动决策依据。
